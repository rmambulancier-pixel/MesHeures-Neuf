- `cd(date)` (mémoïsé par `MH30DataEngine`) : amplitude, pauses, TTE, nuit, IDAJ, paniers, alertes. HS, quatorzaine,

### Correspondance sans réinterprétation
- Par DATE seulement. Le Prévu est lu tel que validé (type et libellé du dictionnaire) ; le Réel tel que saisi (type de
  journée) et calculé par le moteur (TTE, horaires). Aucune heure prévue n'est jamais injectée dans un calcul réel.
- Lecture du Réel par un pont unique `app-v373-reel-lecture.js` : copie figée de `DB.days[date]` et de `cd(date)`,
  aucune écriture. `app-core.js` n'a pas besoin d'être modifié.

### Cas ambigus identifiés
| Cas | Traitement |
|---|---|
| plusieurs fiches, même valeur | une comparaison, toutes les provenances affichées |
| plusieurs fiches, valeurs différentes | ⚠️ conflit, aucune valeur retenue, hors taux |
| aucune prévision, travail réel | 🔴 réel non prévu (compté « sans planning ») |
| aucune prévision, repos/congé réel | ℹ️ non comparable |
| prévision, aucun réel | 🔵 prévu mais aucun réel (« à venir » après aujourd'hui) ; jamais « non travaillé » |
| plusieurs journées réelles possibles | impossible dans le modèle (une clé par date) |
| libellé inconnu / non concerné / férié / formation | ℹ️ non comparable, raison affichée |
| horaires réels incomplets | nature comparée, écart non calculé (signalé) |

## 2. Règles de comparaison (`app-v373-comparaison.js`)

Nature du Prévu (dictionnaire validé) : `JOUR`, `GARDE_SAMU`, `GARDE_COMMERCIALE` → travail ; `REPOS` → repos ;
`CONGES_35H` → congé ; `FERIE`, `FORMATION` → non comparable (le dictionnaire ne dit pas si le jour est travaillé) ;
`applicable=false` (Matin, Après-midi, Récup 39h) et non interprété → non comparable.

Nature du Réel : `T`, `NUIT` → travail ; `REPOS` → repos ; `CP` → congé ; `RC` → repos compensateur ; `MAL` →
maladie ; autre → non comparable.

Ordre : ⚠️ conflit > ℹ️ non comparable > 🔵 prévu sans réel > 🟢 même nature > 🔴 travail réel sur un jour prévu
sans travail > 🟠 autre différence.

Écarts d'heures (TTE réel − durée prévue ; début/fin réels − horaires prévus) : affichés à titre d'information, ils ne
changent jamais la catégorie (aucune tolérance inventée).

## 3. Statistiques
- jours comparables = prévision unique de nature comparable ET journée réelle de nature connue
  (= conformes + différents + réels non prévus sur un jour prévu) ;
- taux de conformité = conformes / jours comparables ; non affiché si aucun jour comparable ;
- hors taux, comptés à part : prévus sans réel (passés), à venir, réels sans planning, conflits, non comparables.

## 4. Séparation Prévu / Réel
Aucune écriture dans `DB.days` ni dans `mesheures_v3` ; aucune journée créée ; aucun calcul réel modifié. Démontré par
les tests (`tests/v373-comparaison.test.js`, `tests/v373-comparaison.browser.js`) : `DB.days` identique octet pour
octet et calculs réels identiques (cd, TTE, HS, amplitude, pauses, nuit, paniers, IDAJ, CP, Paie, quatorzaine,
Smart Control, ROMI1, Compteur) avant et après comparaison de six mois.
