# MesHeures V37.4.0 — Plannings prévisionnels dans le Dossier

Base : tag `v37.3.0` (commit `bad6ce6`, tree `b0be47bd`). Branche `v37.4`. Version 37.4.0 / 3740, révision du cache `37.4.0`.

## Objet
Le Dossier probatoire (PDF signé, imprimable, JSON) restitue les plannings prévisionnels validés comme **pièces de
référence** : ce qui était prévu, jamais une preuve de travail, jamais dans un calcul (heures, HS, paie, comparaison).
Une seule source de données pour les trois exports : `MHDossier.data()` → bloc `plannings`.

## Lecture seule
- Lectures autorisées : `MHPlanning.store().liste()`, `importsListe()`, `analyseLire()` (copies) et `MHPrevuCalendrier.index()`.
- Aucune fonction d'écriture du module Planning n'est appelée (contrôle statique dans les tests).
- La disponibilité des fichiers originaux n'est **pas** vérifiée par le dossier : la vérification existante
  (`verifierSources`, V37.2) réécrit le stockage. Le dossier affiche le dernier état enregistré, présenté comme tel
  (« disponible lors de la dernière vérification enregistrée » / « à vérifier »). Le module V37.2 fait cette vérification
  à chaque démarrage de l'application.

## Liste fermée de champs (`d.plannings`)
- `fiches[]` : id, fichier (nom, type, taille, SHA-256 de l'original), période, salarié (ligne choisie et confirmée par
  l'utilisateur), page, tableau, page lue retournée, importé le, validé le, OCR (moteur, statut), dictionnaire, état de la
  source, nombre de jours, points signalés, journal de lecture, nombre de corrections par origine.
- `journees[]` : date, état (prévu / identique / conflit), toutes les valeurs avec leur planning. Aucune n'est retenue en
  cas de conflit.
- `corrections[]`, `historique[]` (validation, fiche supprimée, analyse rejetée), `importsSansPlanning` (nombre seulement).
- Exclus : titre lu par l'OCR, nom lu, coordonnées, couleurs, référence locale, candidats, avertissements d'analyse.
  Le module Planning ne stocke aucun nom de collègue ; la liste fermée protège aussi d'un texte libre (titre) qui en contiendrait.

## Traçabilité de la lecture
- À la validation, la fiche reçoit le texte **corrigé** ; la lecture OCR d'origine n'existe que dans le journal de l'analyse.
- Origine des corrections :
  - `analyse` : journal de l'analyse (lecture OCR d'origine, avant, après, date, raison) ;
  - `apres_validation` : correction de la fiche datée après sa validation ;
  - `validation` : correction de la fiche sans équivalent dans le journal de l'analyse (reportée à la validation, ou
    datée avant la validation par une horloge revenue en arrière).
- Une correction de la fiche n'est retirée que si elle reprend **à l'identique** (date, champ, valeur) une entrée du journal
  de l'analyse (report fait par la validation). Rien n'est masqué sur la seule foi de l'horloge.
- Analyse retirée : « lecture OCR d'origine indisponible (analyse retirée) ». Fiche sans analyse liée : « (aucune analyse liée) ».

## Section 12 (Intégrité devient 13)
Avertissement, tableau des plannings, empreinte SHA-256 complète de chaque original, journées prévues (conflits sans
arbitrage), corrections, historique des imports, nombre d'imports sans planning validé. Sans planning : une ligne
« Aucun planning prévisionnel enregistré. ». Module absent : « indisponible ».
Conséquence de mise en page : un dossier sans aucune donnée passe de 1 à 2 pages (Intégrité, section courte, reste entière).
